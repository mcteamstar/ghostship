## Context

`install.sh` manages `ga-transport` with a 40-line `podman run` block. `start.sh` duplicates those args as a cold-boot fallback. The two copies will drift. Compose solves this by generating the service definition once and reusing it everywhere.

## Goals / Non-Goals

**Goals:**
- Single source of truth for `ga-transport` container config
- `start.sh` handles all lifecycle states (running, stopped, missing) with one command
- `uninstall.sh` simplified to `compose down`

**Non-Goals:**
- Using Compose for crew containers (`gs-*`) — these are dynamically created at runtime
- Static Compose file — must be generated because the socket path and env vars are machine-specific

## Decisions

**Generated, not static:** The Compose file is written to `${DATA_DIR}/compose.yml` by `install.sh`. It's not committed to the repo. The Podman socket path, port, data dir, ghostship dir, and all env vars are interpolated at generation time using a heredoc — same pattern as the systemd unit.

**`podman compose` not `docker compose`:** `podman compose` is the built-in subcommand added in Podman 4.4. On macOS it requires `--connection <machine-name>` when using a dedicated machine; on Linux with a dedicated instance it needs `CONTAINER_HOST` pointing at the right socket. The compose invocation in `start.sh` and `install.sh` must set these the same way the rest of the script does.

**Podman socket in compose file:** The Podman socket is bind-mounted into the transport container (so the transport can call Podman). In the Compose file this is a `volumes:` entry and a `PODMAN_SOCKET` env var. The socket path is baked in at generation time.

**`--project-name ga`:** Use `--project-name ga` on all compose invocations to ensure the container is named `ga-transport` (Compose's default naming would be `ga-ga-transport` or similar without this).

**Version check:** Add a Podman version check at the top of `install.sh`. Parse `podman --version` output, compare against 4.4.0, exit with a clear message if below.

**`start.sh` simplification:** The entire "ensure Podman service is running" + "podman start or fallback podman run" block is replaced with:
1. Ensure Podman service is running (this stays — compose needs the socket/machine running)
2. `podman compose -f "${DATA_DIR}/compose.yml" up -d`

No more manual cold-boot detection, no more duplicated run args.

## Compose file shape (generated)

```yaml
# Generated by install.sh — do not edit manually
services:
  ga-transport:
    image: localhost/transport:latest
    container_name: ga-transport
    restart: always
    security_opt:
      - label=disable
    ports:
      - "127.0.0.1:${PORT}:${PORT}"
    networks:
      - ga-net
    volumes:
      - ${DATA_DIR}:/data
      - ${GHOSTSHIP_DIR}/academy/agents:/agents:ro
      - ... (all mounts)
      - ${PODMAN_SOCK}:${PODMAN_SOCK}
    environment:
      PODMAN_SOCKET: ${PODMAN_SOCK}
      PORT: "${PORT}"
      ... (all env vars)
networks:
  ga-net:
    external: true
```

All values are substituted by the heredoc in `install.sh` — no shell variable expansion at compose runtime.

## Risks / Trade-offs

**[Risk] `podman compose` behaviour differences across versions** — compose output format and error messages vary. Mitigation: version-gate at 4.4+ and test on both 4.x and 5.x (<host> runs 5.7).

**[Risk] `--project-name` handling** — different compose versions may name containers differently. Mitigation: always pass `--project-name ga` and `container_name: ga-transport` explicitly to force the name.
