## Context

`BearerAuthMiddleware` in `transport/auth.py` dispatches `/files/` requests to `_file_app` before the Bearer check runs (`_dispatch_file` is called before `_dispatch_authenticated` in `handle_http`). This means the transport-level Python code already bypasses Bearer auth for the file route. Yet GET requests to presigned evac URLs return HTTP 401 from `academy.penguin-piano.ts.net`.

The auth layer in front of the transport is Caddy, which acts as a reverse proxy for the main transport port. The academy deployment's Caddy config is generated by `scripts/install.sh` at install time. The generated Caddy config routes all traffic from the public hostname to `ga-transport`, and the main site likely applies a blanket `forward_auth` or `Authorization` header check at the Caddy level that fires before the request even reaches the Python transport. The upload path works because the presigned upload URL carries `sig`+`expires` and Caddy's check is somehow not firing for POST — possibly because the `Unauthorized` string seen in upload responses was the response body from a redirect, not a Caddy auth rejection.

The fix has two parts: confirm and fix the Python transport behaviour, and ensure the Caddy config (or any intermediate proxy) exempts `/files/` from Bearer auth when a `sig` parameter is present.

See proposal.md for motivation.

## Goals / Non-Goals

**Goals:**
- Presigned download URLs work with bare `curl` (no `-H "Authorization: Bearer ..."`)
- Presigned upload URLs work with bare `curl` (consistent with download)
- Behaviour is correct at all layers: Caddy, transport Python middleware, file handler

**Non-Goals:**
- Removing Bearer auth from non-file routes
- Changing the presigned URL signing scheme or token format
- Removing the `X-Transport-Token` internal infrastructure header (that's Caddy→transport, not caller-facing)

## Decisions

### D1: Exempt `/files/` from Bearer auth at the Caddy level when `sig` is present

The Caddy config generated by `install.sh` SHALL include a matcher that exempts requests to `/files/` carrying a `sig` query parameter from any Bearer auth enforcement. Caddy's `expression` matcher can check `{http.request.uri.query}` for the presence of `sig`. The presigned token verifier in the Python transport handles auth for these requests.

**Why at Caddy and not just Python:** The Python transport already does the right thing (`_dispatch_file` bypasses Bearer). The bug is at the Caddy layer. Fixing only the Python side would leave the Caddy rejection in place.

### D2: Verify and document the Python transport path as-is

The `_dispatch_file` → `_file_app` path in `BearerAuthMiddleware.handle_http` is correct and should not be changed. Add a comment documenting the auth bypass intent explicitly, so future readers don't "fix" it.

### D3: Fix applies to both GET and PUT/POST

The matcher must cover all HTTP methods on `/files/`, not just GET. Caddy matchers apply to all methods by default unless restricted — ensure the exemption is not accidentally method-scoped.

## Risks / Trade-offs

- **Caddy config regeneration required** — operators must re-run `./install.sh` to pick up the Caddy config change. Existing deployments will not be fixed until reinstalled. Mitigation: document in release notes; the fix is non-breaking (presigned URLs currently work with the Bearer header, and will continue to do so after the fix).

- **`sig` presence as the exemption trigger** — using `sig`-in-query-string as the Caddy bypass condition means any request with a `?sig=` parameter to `/files/` bypasses Caddy's Bearer check and goes straight to the Python token verifier. The Python verifier then enforces the full HMAC + expiry check — an invalid `sig` gets 403, not 200. This is correct: the token verifier is a stronger gate than Bearer auth (Bearer is a static shared secret; the presigned token is HMAC-scoped to crew, path, operation, and expiry).

- **Upload already working (or appeared to work)** — the upload path returning `Unauthorized` as a prefix in the response body appears to be a side effect of a Caddy redirect response, not a genuine auth failure, since the upload data was delivered. Fixing the download path may reveal that uploads were also silently failing in some configurations. Mitigation: test both directions after the fix.

## Migration Plan

1. Update `scripts/install.sh` to include the `/files/` + `sig` Caddy exemption in the generated site config.
2. Re-run `./install.sh` on the academy host to regenerate the Caddy config and reload Caddy.
3. Verify: `curl` a presigned evac URL without `-H "Authorization: Bearer ..."` — should return HTTP 200.
4. Verify: `curl -X POST` a presigned supply URL without `-H "Authorization: Bearer ..."` — should return HTTP 200.

No crew restarts needed. No changes to existing presigned URL format.
