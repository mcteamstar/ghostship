## Context

`ghostship.conf.example` has grown to 57 documented variables. The bloat falls into three categories:

1. **Constants** — values that are effectively fixed in the standard install (e.g. `TRANSPORT_DATA_DIR=/data`, `PODMAN_SOCKET`, `GA_CREW_AGENT`). These are not really configurable without also changing volume mounts or internal wiring. They belong in code comments, not `ghostship.conf`.
2. **Internal tuning knobs** — KiroCrew internals (`GA_SUBAGENT_*`, `GA_RESOURCE_*`, `GA_SPAWN_MIN_MEMORY_GB`) and rate-limit fine-tuning (`GA_RATE_LIMIT_*`). Defaults are correct for all installs. Exposing them invites operators to misconfigure things.
3. **Auto-generated** — `GA_TRANSPORT_SECRET` is generated by install.sh and should never be set manually.

A further subset of genuinely operator-facing vars are documented but broken: `GA_ORDERS_DIR` and TLS cert/key vars are written into compose as env vars but the host paths are never mounted, so the transport can't read them.

**Note:** a follow-on change will formally separate constants (extracted to a constants file) from operator config. This change is the first pass: prune the conf.example surface and fix the broken wiring for vars that remain.

## Goals / Non-Goals

**Goals:**
- Remove internal tuning knobs, constants, and auto-generated vars from `ghostship.conf.example`
- Fix `GA_ORDERS_DIR` and `GA_TLS_CERTFILE`/`GA_TLS_KEYFILE` with conditional volume mounts
- Fix inaccurate `lifecycle.py` comment about TTL floors
- Update docs to match

**Non-Goals:**
- Formally extracting constants to a separate file (follow-on change)
- Adding new config vars
- Changing any runtime behaviour beyond the volume mount fixes

## Decisions

### D1 — Prune conf.example to ~32 operator-relevant vars

Remove: `GA_PREWARM_ENABLED`, `GA_PREWARM_TTL_SECS`, `GA_RESOURCE_*`, `GA_SPAWN_MIN_MEMORY_GB`, `GA_SUBAGENT_*`, `GA_TRANSPORT_SECRET`, `TRANSPORT_DATA_DIR`, `PODMAN_SOCKET`, `GA_ENABLE_SECURITY_HEADERS`, `GA_TLS_MIN_VERSION`, `GA_CREW_AGENT`, `GA_MACHINE_NAME`, `GA_DASHBOARD_PORT_RANGE_*`, all `GA_RATE_LIMIT_*` vars.

Move to docs-only (advanced/dev): `KC_IMAGE`, `KC_BASE_IMAGE`.

These vars stay in `config.py` and remain functional — they're just not surfaced in the operator-facing conf file.

### D2 — GA_ORDERS_DIR gets a conditional volume mount

When `GA_ORDERS_DIR` is set, `install.sh` adds `- ${GA_ORDERS_DIR}:/mnt/orders:ro` to the compose volume block and rewrites the env var to the fixed container path `/mnt/orders`. Require absolute path; warn if path doesn't exist at install time.

### D3 — TLS cert/key get a conditional volume mount

When both TLS vars are set, mount their parent directory as `/mnt/tls:ro` and rewrite both vars to container-side paths. Require same parent directory; error if they differ.

### D4 — Fix lifecycle.py comment only; no code floor

The "Both TTLs floor at one hour" comment is wrong. Fix the comment; don't add a floor to `_TASK_TIMESTAMP_TTL_SECS` — that's a behaviour change.

## Risks

- Operators who previously set `GA_ORDERS_DIR` expecting it to work were already broken. The volume mount fix is strictly better.
- TLS same-directory requirement is new. Rare edge case; error message will be clear.
- Removing vars from conf.example doesn't remove them from config.py — they remain functional, just not documented in the operator-facing file.
