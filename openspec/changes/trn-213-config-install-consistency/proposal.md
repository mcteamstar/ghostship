## Why

`ghostship.conf.example` has grown to 57 documented variables. Many are internal
implementation details, KiroCrew tuning knobs, or plumbing that operators should never
touch. The bloat obscures what actually matters and makes the install experience
intimidating. Separately, a small number of genuinely operator-facing vars are documented
but silently broken — they reach `install.sh` but never land in `compose.yml` or get the
required volume mounts.

This change does two things: prune the config surface to ~32 operator-relevant vars, and
fix the handful of broken vars that remain.

## What Changes

### Pruned from ghostship.conf.example (moved to code comments or removed entirely)

These are internal tuning knobs, auto-generated values, or implementation details that
operators should never set:

- `GA_PREWARM_ENABLED`, `GA_PREWARM_TTL_SECS` — prewarm is implicit since TRN-194; no
  operator action needed
- `GA_RESOURCE_PRESSURE_GB`, `GA_RESOURCE_CRITICAL_GB`, `GA_SPAWN_MIN_MEMORY_GB` —
  KiroCrew memory gate internals; the conf.example comment already says "leave at 0"
- `GA_SUBAGENT_TIMEOUT_SECS`, `GA_SUBAGENT_MAX_TURNS` — KiroCrew internals
- `GA_TRANSPORT_SECRET` — auto-generated by install.sh, never set by operator
- `TRANSPORT_DATA_DIR` — pinned to /data in the standard install; changing it requires
  editing compose.yml manually anyway
- `PODMAN_SOCKET` — internal plumbing; operators using a dedicated machine never touch this
- `GA_ENABLE_SECURITY_HEADERS` — should always be on; not a tuning knob
- `GA_TLS_MIN_VERSION` — sensible default (1.2); no real operator use case
- `GA_CREW_AGENT` — internal KiroCrew config name
- `KC_IMAGE`, `KC_BASE_IMAGE` — useful for dev/testing but not for production operators;
  document in docs/configuration.md as advanced/dev-only
- `GA_RATE_LIMIT_ENABLED`, `GA_RATE_LIMIT_LOGIN_GET`, `GA_RATE_LIMIT_LOGIN_POST`,
  `GA_RATE_LIMIT_MCP`, `GA_RATE_LIMIT_FILES`, `GA_RATE_LIMIT_CREW_API` — internal
  tuning; defaults are correct for all installs
- `GA_MACHINE_NAME` — no reason to change the dedicated machine name
- `GA_DASHBOARD_PORT_RANGE_START`, `GA_DASHBOARD_PORT_RANGE_SIZE` — internal port
  allocation; operators don't need to tune this

### Fixed — broken vars that remain after pruning

- `GA_ORDERS_DIR` — add conditional volume mount in install.sh (`/mnt/orders:ro`),
  rewrite env var to container path. Operators supply a host absolute path; transport
  sees `/mnt/orders`.
- `GA_TLS_CERTFILE` / `GA_TLS_KEYFILE` — add conditional volume mount (`/mnt/tls:ro`),
  require same parent directory, rewrite paths to container-side basenames.
- Fix `lifecycle.py` comment: "Both TTLs floor at one hour" — only warm-marker TTL is
  floored; `_TASK_TIMESTAMP_TTL_SECS` has no floor. Fix the comment, don't add a floor.

### Docs / conf.example

- Remove pruned vars from `ghostship.conf.example`
- Update `docs/configuration.md` to match
- Add note that `PORT` controls Caddy host port only; transport always listens on 64057
  inside its container
