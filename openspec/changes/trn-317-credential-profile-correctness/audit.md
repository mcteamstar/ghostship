# Credential path audit

- `launch` resolves one backend/profile, records it in the crew registry and now returns it. A missing named profile must not start or consume a default-profile login.
- Codex and Claude OAuth completion stores an encoded archive; launch previously looked up the selected envelope but injected the shared legacy archive. Kiro device credentials are encoded SQLite rows.
- All three device-flow completion handlers previously wrote shared legacy state and suppressed profile-store write failures. Kiro reauthentication propagates to matching running crews; Codex and Claude previously did not propagate their completed credentials.
- Stopped crew homes persist across restarts. OAuth profile rotation therefore requires refreshing the selected credential when the crew wakes; otherwise it may retain an older identity.
- API keys and Claude setup tokens are injected into the container environment at creation. A container retains its original environment, so replacing the credential store entry does not itself update the container. Recovery now checks the selected static value without logging it and refuses a mismatch before starting the container; applying a rotated static credential still requires a new container with its workspace preserved.
- Logout targets a backend/profile and removes the legacy archive only for default. Login initiation, completion and logout are serialized around profile state changes; synthetic concurrency tests cover an older logout racing a later commit. A running crew remains usable after its profile is logged out, while a stopped crew requires a usable profile before restart.
- Legacy `ga-codex-auth` and `ga-claude-auth` archives are read only for an absent default envelope and are left intact. The older flat envelope migration moves `credentials/<backend>.json` to the default slot. Upgrades are forward-only, so older versions need not read the migrated store.
- The profile-aware Kiro device-login route previously rejected a new or rotated profile whenever the shared default auth file existed; it now permits the flow and replaces only the selected profile upon completion. The legacy bare login route retains its existing guard.
- Synthetic tests exercise both orders of same-profile logout versus completion for all three backends, scoped Kiro/Claude/Codex propagation, persistence and propagation failure retries, and static key/setup-token rotation and logout isolation. Static credential changes cannot update an existing container environment and require a new crew with the workspace transferred.
- Verification: 1,545 unit and focused integration tests passed, with one skipped; subsequent focused route tests also cover Kiro write failure/retry and redaction of a synthetic exception value. The existing E2E suite passed on Corsair (30 passed, 9 skipped), including its launch response check. Two-profile OAuth payload selection has synthetic integration coverage; an isolated live two-profile OAuth fixture remains outstanding.
