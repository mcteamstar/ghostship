# Python Modules Specification

## Purpose

`install.sh` logic (compose.yml generation, Caddy config, Podman provisioning,
and wizard I/O) SHALL be implemented as tested Python modules under `bin/lib/`
so that `install.sh` is a thin shell entry point and individual sections are
independently unit-testable without running Podman or Docker.

## Requirements

### Requirement: install.sh is a thin entry point
`install.sh` SHALL be a shell entry point of ≤100 lines. It SHALL delegate
compose.yml generation, Caddy config generation, Podman provisioning, and
interactive wizard I/O to Python modules under `bin/lib/`. It SHALL NOT contain
any bash heredoc that renders YAML or JSON.

#### Scenario: No heredoc YAML in install.sh
- **WHEN** a reader inspects `bin/install.sh`
- **THEN** no `cat > ...` heredoc that produces YAML or JSON content is present

#### Scenario: Line-count gate
- **WHEN** the install.sh line count is measured
- **THEN** it is ≤100 lines (excluding blank lines and comments)

### Requirement: compose.yml generated by Python module
`bin/lib/compose.py` SHALL produce the compose.yml rendered from a structured
config dict (not string interpolation). It SHALL accept configuration as either
env-var dict or a Python dataclass and return a validated YAML string.

#### Scenario: compose.py produces correct service structure
- **WHEN** `compose.py` is called with valid config inputs
- **THEN** the output YAML contains `ga-transport`, `ga-portal`, and `ga-radar`
  services and both `ga-portside` and `ga-starboard` networks

#### Scenario: compose.py is unit-testable without Podman
- **WHEN** `tests/unit/test_compose.py` runs in CI (no Podman)
- **THEN** tests assert the rendered YAML structure and pass without any Podman
  installation

#### Scenario: compose.py validates required fields
- **WHEN** a required config field (e.g. `PODMAN_SOCK`) is absent or empty
- **THEN** `compose.py` exits with a non-zero status and a clear error message
  before writing any file

### Requirement: Caddy config generated by Python module
`bin/lib/caddy.py` SHALL produce `initial-config.json` as a Python dict
serialised to JSON. It SHALL support all four `GA_PORTAL_TLS_MODE` values
(`off`, `internal`, `tailscale`, `acme`) and the API-key-gated vs open route
variants.

#### Scenario: caddy.py produces gated routes when API key is set
- **WHEN** `caddy.py` is called with a non-empty `GA_API_KEY`
- **THEN** the output JSON contains Bearer-gated route handlers for `/mcp*`
  and `/files/*` and a 401 reject handler for unauthenticated requests

#### Scenario: caddy.py produces passthrough routes when no API key
- **WHEN** `caddy.py` is called with no `GA_API_KEY`
- **THEN** the output JSON contains passthrough reverse-proxy handlers for
  `/mcp*` and `/files/*` with no Bearer check

#### Scenario: caddy.py is unit-testable without Caddy
- **WHEN** `tests/unit/test_caddy.py` runs in CI (no running Caddy)
- **THEN** tests assert the JSON structure for all TLS modes and pass

### Requirement: Podman provisioning implemented in Python
`bin/lib/podman_setup.py` SHALL implement Podman machine/instance provisioning,
socket path resolution, and dedicated-instance wiring. It SHALL NOT use
`eval` on any external process output.

#### Scenario: podman_setup.py resolves socket path without eval
- **WHEN** `podman_setup.py` runs on Linux with a dedicated instance
- **THEN** the socket path is derived without calling `eval` on any
  subprocess output

#### Scenario: podman_setup.py errors clearly on missing socket
- **WHEN** the Podman socket does not exist after the bounded retry
- **THEN** `podman_setup.py` exits with a non-zero status and a diagnostic
  message naming the socket path and the recommended debug command

### Requirement: eval injection surface eliminated
The `eval "$_RESOLVED"` pattern in `install.sh` (used to ingest yaml_config.py
output) SHALL be removed. Python modules SHALL import `yaml_config` directly
and receive configuration as Python objects, never as shell-eval'd strings.

#### Scenario: No eval of subprocess output in install.sh
- **WHEN** `bin/install.sh` is inspected
- **THEN** no `eval "$(..."` or `eval "$(...)"` pattern is present that
  evaluates the output of a subprocess (yaml_config.py or any Python module)

### Requirement: Agent-backends and portal-host logic in Python
`bin/lib/agent_backends.py` and `bin/lib/portal_host.py` SHALL implement the
logic currently in `agent_backends.sh` and `portal_host.sh`. The shell files
SHALL be retained as one-line delegators during the transition for callers
(e.g. tests) that source them directly, and SHALL be documented as deprecated.

#### Scenario: agent_backends.py normalise produces identical output to shell
- **WHEN** `agent_backends.py` normalises a comma-separated backend list
- **THEN** the result matches the output of `agent_backends_normalise()` from
  `agent_backends.sh` for the same input

#### Scenario: portal_host.py is-loopback agrees with yaml_config.py
- **WHEN** `portal_host.py` tests a host address for loopback
- **THEN** the result matches `yaml_config.py is-loopback` for the same input

### Requirement: All new Python modules are independently unit-testable
Each module under `bin/lib/` SHALL have a corresponding unit test file in
`tests/unit/` that exercises it without Podman, Docker, Caddy, or a live
transport.

#### Scenario: tests/unit/test_compose.py covers compose generation
- **WHEN** the test suite runs
- **THEN** `tests/unit/test_compose.py` exists, imports `bin.lib.compose`,
  and asserts rendered YAML structure for at least three config variants

#### Scenario: tests/unit/test_caddy.py covers Caddy config generation
- **WHEN** the test suite runs
- **THEN** `tests/unit/test_caddy.py` exists, imports `bin.lib.caddy`, and
  asserts JSON structure for all TLS mode / API-key combinations

#### Scenario: tests/unit/test_agent_backends_parity.py passes with Python module
- **WHEN** the test suite runs after `agent_backends.py` is introduced
- **THEN** `tests/unit/test_agent_backends_parity.py` asserts that Python and
  shell implementations return identical output for the same inputs
